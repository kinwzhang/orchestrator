# Resolve foreseeable source overlap before worker dispatch

## Human direction

Identify and resolve foreseeable overlap in the plan before issuing implementation worker instructions. Do not routinely defer known overlap to an unplanned reconciliation worker after implementation.

## Planning gate

Before dispatch, inventory required changes from active and retained source branches, exact baseline commits, overlapping files/interfaces and all behavior that must survive final assembly. Include paused product work when the orchestrator repairs itself on another branch.

Settle ownership, shared interfaces, baseline and integration order. Assign overlapping file changes to one owner, or explicitly serialize dependent assignments against committed prerequisite interfaces. Specify the combined target behavior and regression suites. Separate worktrees protect source preservation but do not remove semantic overlap.

Record an overlap/dependency matrix and concrete handoffs in the approved package and dispatch records. Integrator verifies these prerequisites before launch. Parallelize only independent scopes and permitted preparation. Stop on unresolved known overlap rather than issuing ambiguous source instructions.

Actual code conflicts cannot always be resolved before implementation exists. When an unforeseen conflict appears, return it to the declared owners under a bounded integration assignment, with the competing commits and expected combined behavior. Do not let an integrator silently repair source, drop a fix or replace whole files. A separate reconciliation role is exceptional and explicitly planned/approved, not the default remedy for omitted dependency analysis.

## Acceptance example

Model-preferences work and lifecycle repair both modify shared contracts/config/workflow consumers on different ancestries. Before repair dispatch, inventory the retained product commit and fixes, choose staged integration/ownership, and require both behavior suites on the final candidate. If the chosen phase intentionally defers product integration, explicitly record its future owner, dependency and cost before approval rather than presenting it later as a new surprise.

## Current disposition

This requirement records a planning lesson; it does not rewrite approved history or authorize source changes, another worker or live carry-forward execution. For already-produced overlapping work, explicitly amend the existing owner's/integrator's plan before integration. Do not reset budgets or create a fresh reconciliation allowance by renaming the assignment.
